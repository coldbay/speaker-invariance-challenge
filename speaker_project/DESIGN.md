# 동일 발화의 화자 귀속 안정성 — 확정 방향과 실험 설계

작성일: 2026-10-29 (Asia/Seoul)

후속 수정: 사용자가 예시의 대화 자연스러움을 지적했다. 이력 재배열을 본 과제로 삼는 부분은 재검토하며, 현재 description은 원래 순서의 자연 대화에서 질문/답변 주도권이 바뀌는 구간을 평가하는 방향이다. [NATURAL_CONVERSATION_REVIEW.md](NATURAL_CONVERSATION_REVIEW.md)를 우선 참고한다. 아래는 이전 구체화안과 보조 진단 설계로 보존하며 자연 대화에서 검증된 결과가 아니다.

상태: 사용자가 화자 구분 주제로 복귀했다. 이 문서는 현재의 우선 설계다. 보컬 변환 결과와 코드는 보존하지만 추가 보컬 실험은 진행하지 않는다. 화자 구분 데이터 구성·모델 실행·방법의 개선은 아직 검증하지 않았다.

## 1. 연구 질문

‘대화 이력을 재배열했을 때, 동일한 평가 발화와 후속 발화의 올바른 화자 귀속이 유지되는가? 이력에 민감한 판단을 화자 기준 갱신에 반영하지 않으면, 정확도를 유지하면서 후속 오류를 줄일 수 있는가?’

현재 설명문: [DESCRIPTION.md](DESCRIPTION.md). 개별 점수 비교만으로 독창성을 주장하지 않고 입력 구성, 평가의 성공 조건, 제어에 쓰는 증거를 구체화한다.

## 2. 기여 후보와 주장 범위

| 영역 | 이번 설계 | 기존 내용과 겹치는 부분 | 추가로 검증할 내용 |
|---|---|---|---|
| 평가 데이터 | 앞부분만 재배열하고 target/suffix 오디오와 기준 음성을 고정 | 합성 대화, 대조·반사실 평가 자체는 기존 | 같은 녹음 목록의 이력 구성에 따른 실제 화자 배정 변화를 재현하는가? |
| 평가 기준 | 짝의 두 조건에서 모두 정답이어야 성공 | 정확도·일관성 지표의 원리는 기존 | 안정적으로 틀리는 방법을 보상하지 않으면서 평균 정확도가 감추는 실패를 보여주는가? |
| 개선 방법 | 이력 재배열에 대한 판단 일치 여부와 음성 증거로 외부 기준 갱신 제어 | 신뢰도 기반 갱신, 음성 검증, 캐시 관리 자체는 기존 | 신뢰도·음성 정보만 사용하는 같은 비용의 방법보다 추가 이득이 있는가? |
| 오류 분석 | 고정 suffix의 오류와, 온라인 추적기의 기준 갱신에 따른 누적 오류를 분리 | 온라인 오류 전파는 오래된 문제 | 실제 사용한 외부 추적기에서 어떤 갱신이 후속 오류를 유발했는가? |

검색에서 정확히 같은 조합을 찾지 못했다는 사실은 독창성의 증거가 아니다. 설계의 차이를 명확히 기술하되, 방법의 새로움은 관련 연구의 세부 알고리즘과 최종 구현을 추가 비교해야 한다.

## 3. 과제 정의와 정보량

첫 트랙은 **기준 음성이 제공된 2인 화자 귀속**이다. 각 인물의 짧은 기준 음성 2개와 그 구간·등록 ID를 모든 방법에 제공한다. 기준 음성은 평가 발화와 다른 녹음이어야 한다. 이를 사전 등록 없는 일반 diarization이라고 부르지 않는다.

- 입력: 등록 음성, 합성 세션 오디오, 발화 경계. 화자 수는 알려진 2명이다.
- 출력: 평가 발화마다 등록 화자 A/B 중 하나. 기준 음성 자체는 평가 정확도에 포함하지 않는다.
- 제외: 동시 발화, 새 화자의 등장, VAD 성능 비교, 발화 경계 추정, 실제 한국어 상담 일반화.
- 반드시 예측: 불확실한 발화도 출력해야 한다. 메모리 갱신을 안 하는 것과 답을 안 하는 것은 다르다. 답을 안 하면 실패로 계산한다.
- 타임스탬프·분할·등록 정보는 모든 방법에 동일하게 제공한다. 통합 모델이 자체 구간을 반환하면 공통 기준 발화로 변환한 규칙과 실패를 기록한다.
- 생성된 S01/S02 같은 임의 ID는 등록 기준 음성만 사용해 A/B로 대응한다. 평가 발화의 정답으로 유리한 매핑을 찾지 않는다. 대응이 불가능하면 실패로 기록한다.

이 범위를 좁힌 이유는 주제의 독창성을 과장하려는 것이 아니라, 입력 이력의 영향과 외부 기준 갱신의 효과를 VAD·경계 오류와 분리해 검증하기 위해서다.

## 4. 짝 데이터 구성

공통 등록 음성 + 이력(prefix) + 평가 발화(target) + 후속 발화(suffix).

두 조건 X/Y에서:

1. 등록 음성, target, suffix를 샘플 단위로 동일하게 유지한다.
2. prefix는 동일한 원본 녹음 목록을 사용하고 순서만 바꾼다.
3. 가능하면 A/B 교대 순서를 동일하게 유지하고 같은 화자 안에서 녹음 순서를 바꾼다.
4. 발화 사이 무음 길이를 고정한다. 같은 녹음 목록의 순열이므로 전체 길이와 화자별 노출량, target 시작 시각이 동일하다.
5. 한 세션 안에서 같은 파형을 복사해 반복 발화로 사용하지 않는다. X/Y 사이에서 같은 오디오를 공유하는 것은 통제된 짝 설계의 일부다.

예시(기호는 실제 다운로드된 음성이 아닌 구성 설명):

```text
X: 등록음성 | A:p → B:p → A:q → B:q | A:r | 동일한 후속 발화들
Y: 등록음성 | A:p → B:q → A:q → B:p | A:r | 동일한 후속 발화들
```

prefix의 녹음 목록·화자 교대 순서는 같지만 인접한 발화의 문장 반복 구성이 다르다. target A:r와 뒤의 음성은 바뀌지 않는다. p/q는 각 화자가 독립적으로 읽은 같은 문장이고, A:p와 B:p는 다른 파형이다. 등록 음성과 r은 prefix에 등장하지 않는다.

첫 데이터 후보는 VCTK 0.92다. 모든 문장이 공통인 것은 아니므로 실제 공통 대본과 독립 녹음 수를 먼저 조사한다. 공통 문장이 부족하면 완전한 위 예시를 만들었다고 주장하지 않고, 명시된 저·고 어휘 중복 조건으로 조정한다. 문장·어휘 중복과 의미·주제 유사성을 구분한다.

개발·평가 화자는 분리한다. 같은 원본 녹음, 같은 원본의 다른 마이크 버전, 짝 X/Y는 데이터 분할을 넘나들지 않는다. 공통 문장 일부가 공유되면 그 사실을 공개한다. 두 조건의 비교는 자연스러운 실제 대화가 아닌 진단적 구성이고, 의미 단서만의 인과 실험은 아니다.

## 5. 방법 후보: 맥락 민감도를 갱신 근거로 사용

핵심 차별화 후보는 ‘음성으로 보정’ 자체가 아니라, **같은 대상 발화의 판단이 과거 이력을 재배열하면 변하는지**를 현재 판단의 신뢰 근거로 사용하는 것이다.

외부 추적기를 사용한다. 통합 모델의 내부 hidden state나 학습된 speaker memory를 수정했다고 표현하지 않는다.

### 절차

1. 각 화자의 등록 음성으로 고정 기준 c0를 만들고, 별도로 갱신 가능한 기준 c를 유지한다.
2. 현재 대상 발화를 포함한 입력을 원래 순서로 처리한다(m0).
3. 기준 음성과 현재 발화는 고정하고, 과거 prefix의 완결 발화 블록만 재배열한 보조 입력을 처리한다(m1). 기준 대응을 맞춘 화자 결과를 비교한다.
4. 현재 발화의 음성 임베딩과 c0/c의 유사도 및 후보 간 차이를 계산한다.
5. m0/m1이 불일치하면 맥락 민감으로 표시하고 해당 발화로 기준을 갱신하지 않는다. 출력은 사전에 고정한 규칙에 따라 음성 후보(음성 margin이 충분할 때) 또는 원래 m0를 사용한다.
6. 두 판단이 일치하고 음성 증거도 동의할 때만 해당 화자의 c를 갱신한다. 일치하지만 음성 증거가 충돌하면 출력과 갱신을 분리하고 갱신하지 않는다.

같은 답을 반복하는 모델도 잘못된 답을 낼 수 있으므로, ‘일치=정답’으로 취급하지 않는다. 등록 음성의 음향 근거 및 최종 정답 평가를 반드시 함께 사용한다.

### 추론 시 누수 방지

- 보조 이력의 재배열은 현재 입력의 공개 발화 경계로 만든다. 정답 화자 ID로 묶어 재배열하지 않는다.
- 개발 기준으로 고정한 순열/seed를 사용한다. target을 자르거나 파형을 바꾸지 않는다.
- 평가 세트의 짝 상대편 또는 그 정답을 조회해 더 맞는 답을 고르지 않는다. 각 입력을 독립적으로 초기화한다.
- 온라인 추적에서는 현재까지의 음성만 사용한다. suffix는 그 시점 이후에 도착할 음성으로, target 시점의 결정에 미리 넣지 않는다.
- 오프라인 통합 모델의 전체 세션 결과는 별도 진단 행으로 둔다. 미래를 보는 방법을 동일한 온라인 지연의 방법처럼 비교하지 않는다.

### 최소 구현과 확장

최초 진단은 음성 임베딩 기준 방법과 통합 모델을 짝 데이터에 적용하는 것까지다. 맥락 민감도가 관측돼야 보조 이력과 갱신 제어의 필요성을 평가할 근거가 생긴다. 외부 추적기는 같은 입력/결정 주기를 쓰고 갱신 규칙만 바꿔 대조한다.

통합 모델 후보는 MOSS-Transcribe-Diarize 0.9B이며 가중치·입출력·환경을 먼저 확인한다. 임베딩 모델 후보는 공개 ECAPA 계열로 두고, 가중치 접근성과 서버 호환성을 확인한 뒤 고정한다. 현재 둘 다 본 프로젝트에서 실행하지 않았다.

## 6. 필요한 대조군

| 방법 | 확인할 질문 |
|---|---|
| 등록 음성 기반 임베딩, 기준 고정 | 맥락을 사용하지 않는 단순 방법만으로 충분한가? |
| 같은 추적기, 매번 갱신 | 무조건 갱신이 후속 오류를 늘리는가? |
| 같은 추적기, 음성 margin/신뢰도만 사용 | 일반적인 신뢰도 제어로 해결되는가? |
| 같은 추적기, 맥락 판단 일치 여부만 사용 | 음성 검증 없이도 이득이 있는가, 안정적으로 틀리는가? |
| 음성 검증 + 맥락 판단 일치로 갱신 | 두 증거의 결합이 필요한가? |
| 같은 연산 횟수의 단순 다중 뷰 투표 | 개선이 추가 추론 횟수 때문만은 아닌가? |
| 통합 모델 전체 세션 출력 | 오프라인 맥락 민감도 진단. 온라인 결과와 별도 표기 |

반복 추론이 추가되는 만큼 입력 음성 길이, 모델 호출 수, 처리 시간, GPU 메모리, 지연을 공개한다. 같은 비용의 투표보다 못하면 제어 규칙의 필요성이 입증되지 않은 것으로 기록한다.

## 7. 리더보드

우선 순위 지표는 **짝 동시 정답률**이다. 대상/등록 화자를 균형 있게 구성하고, 각 target과 suffix 발화의 정답을 기준으로 두 조건 모두 맞았을 때만 해당 짝의 성공으로 계산한다. 먼저 짝 세션별 평균을 구하고 화자 조합별로 집계한다. 같은 화자 조합에서 만든 여러 순열을 독립 사례처럼 부풀리지 않는다.

예측이 명확한 A/B인 경우 각 발화 i에 대해:

- 개별 정답률: X/Y 각각의 올바른 귀속 비율.
- 짝 동시 정답률: mean(correct_X(i) AND correct_Y(i)).
- 맥락 변경률: mean(pred_X(i) != pred_Y(i)). 임의의 출력 ID를 등록 기준으로 정렬한 뒤 계산.
- 안정 오답률: mean(pred_X(i) == pred_Y(i) AND NOT correct_X(i)). 정답이 고정된 짝에서 정의한다.
- 후속 오류율: 고정 suffix의 잘못된 귀속 비율. X/Y를 모두 제시한다.
- 정상 배정 훼손률: 제어를 추가하기 전 맞았던 발화를 틀리게 바꾼 비율.
- 호출 수·시간·메모리·지연·실패율.

출력 누락·등록 기준 대응 실패도 오답으로 계산하며 제외하지 않는다. 항상 A를 출력하는 방법과 등록 음성 고정 기준 방법을 함께 넣어 지표가 안정 오답을 보상하지 않는지 확인한다.

온라인 실험에만 복구 발화 수와 메모리 갱신 로그를 추가한다. offline 출력에서 앞부분과 뒷부분이 함께 바뀌었다는 사실만으로 순차적 오류 전파를 입증했다고 하지 않는다.

예정 표:

| 방법 | 짝 동시 정답률 ↑ | 개별 정답률 ↑ | 맥락 변경률 ↓ | 안정 오답률 ↓ | 후속 오류율 ↓ | 정상 배정 훼손 ↓ | 시간·호출 수 |
|---|---|---|---|---|---|---|---|
| 측정 전 | — | — | — | — | — | — | — |

## 8. 소형 진단과 진행 기준

데이터 확보 후 개발 화자와 평가 화자 조합을 분리하고, 예를 들어 평가에서 겹치지 않는 3개 화자 쌍 × 4개 구성 = 12짝(24개 세션)을 첫 목표로 삼는다. 이는 설계 예시이며 실제 확보 표본 수는 아직 확정하지 않았다. 동일 입력 반복으로 디코더 자체의 변동도 확인한다.

1. 기준 음성과 target이 다른 녹음인지, X/Y의 target/suffix가 샘플 단위로 같은지 확인한다.
2. 일반 조건의 정확도와 짝 조건의 민감도를 먼저 측정한다.
3. 기본 음성 방법이 매우 잘하고 통합 모델도 맥락에 안정적이면, 복잡한 갱신 제어를 정당화할 실패가 부족하다고 판단한다.
4. 실패가 관측되면 개발 세트에서만 threshold·갱신률·보조 이력 규칙을 정하고 평가에는 고정 적용한다.
5. 제어의 추가 이득이 없다면 진단 데이터와 실패 분석 범위로 제출 설명을 조정한다. 결과를 성공으로 포장하지 않는다.

## 9. 기존 연구와 구분할 문장

- SpeakerSleuth: 언어 맥락에 치우친 화자 일관성 판단을 평가한다. 이번에는 기준 음성이 주어진 실제 발화 귀속을 동일 오디오의 재배열 이력 쌍에서 평가하며 두 조건 동시 정답을 요구한다.
- HEAR: 목소리를 교체하는 반사실 사례 등으로 화자 관련 판단·추론을 평가한다. 이번에는 평가 목소리와 발화 자체를 바꾸지 않고, 같은 과거 녹음들의 순서만 바꿔 후속 귀속을 비교한다.
- AG-LSEC: 음성 화자 점수로 언어 기반 화자 오류 보정을 강화한다. 이번에는 보조 이력에서 판단이 유지되는지를 외부 기준 갱신의 추가 증거로 평가한다.
- Streaming Sortformer 및 기존 온라인 추적: 화자 캐시·기준 관리와 일관성 자체는 기존 주제다. 이번에는 맥락 재배열에 대한 판단 불안정성을 제어 근거로 쓰는 구체적 결합을 비교할 계획이다.

위 차이는 선택한 관련 연구와의 설계 비교다. 분야 전체에서 동일 방법이 없다는 증명은 아니다.

## 10. 제출 범위

과제 요구: 설명 HTML, 실제 결과 리더보드, 코드, 평가 음성 데이터, 평가 코드, 개인 저장소 링크. 사용 가능한 데이터의 라이선스·출처와 재배포 조건을 확인하고 평가 데이터 파일을 포함해야 한다. 다운로드 스크립트만으로 필수 평가 데이터 포함 조건을 충족했다고 간주하지 않는다.

현재는 설계 문서가 준비된 상태다. 화자 실행 코드와 실제 평가 결과는 아직 없다. 제출 description은 계획형으로 작성하고, 실험 후 확인된 기여만 결과형으로 바꾼다.
