01

개요

문제: 통합 모델이 만든 새로운 질문

기존 화자 인식은 발화를 잘라 하나씩 음성 임베딩을 비교했습니다.
이 방식에서는 대화 앞에 무음을 붙이거나 등록 음성의 순서를 바꿔도 결과가 달라질 이유가 없습니다.

그런데 회의록 작성에 쓰이는 최신 통합 모델은 전사와 화자 분리를 함께 수행하며,
등록 음성과 대화 전체를 하나의 문맥으로 처리합니다.
그렇다면 위치나 순서처럼 사람에게는 아무 의미 없는 변화에도 같은 발화를 같은 사람에게 귀속할까요?

왜 기존 평가로는 보이지 않았나

  • DER, cpWER 등 화자 분리 표준 지표는 한 번 실행한 결과의 오류율만 잽니다.
  • 기존 연구의 '일관성'은 대개 한 녹음 안에서 같은 사람에게 같은 ID를 유지하는지를 뜻합니다.
    입력이 조금 바뀌었을 때 같은 답을 내는지는 따로 묻지 않습니다.
  • 통합 모델은 같은 입력에 항상 같은 출력을 내므로(결정적 디코딩),
    한 번만 평가하면 안정적으로 보입니다.

핵심 관찰 — 통합 모델 MOSS는 한 가지 입력에서 91.4%를 맞히지만,
대화 내용은 그대로 둔 10가지 변형 모두에서 맞힌 발화는 67.1%뿐입니다.
처음 보는 4인 회의 8개 중 5개에서 화자 귀속이 바뀌었습니다.

이 챌린지의 기여

  1. 불변성 평가 축 — 내용 보존 변형(앞 무음 0–4초, 등록 순서 역순) 10가지를 정의하고,
    모든 변형에서 맞힌 비율인 불변 정답률을 대표 지표로 삼습니다.
  2. 실제 회의 기반 데이터 — AMI 회의의 연속 구간에서 질문↔답변 역할이 바뀌는 대화와 발화 겹침이 많은 대화를 골랐고,
    화자가 겹치지 않는 미관측 평가 세트를 따로 두었습니다.
  3. 오류 원인의 분리 — 통합 모델의 실패를 '등록 음성을 화자 ID에 연결하지 못함'과 '대화 안에서 잘못 귀속함'으로 나눠 보고합니다.
  4. 열린 과제 — 간단한 임베딩 재연결로 Main 트랙의 불변성은 회복되지만,
    겹친·짧은 발화(Hard 트랙)에서는 어떤 방법도 불변 정답률 65%를 넘지 못합니다.

확인한 범위의 선행연구에서는 통합 음성인식 모델의 등록 기반 화자 귀속을 이런 내용 보존 변형으로 평가한 벤치마크를 찾지 못했습니다(아래 관련 연구 참고).

정리
  • 통합 모델은 대화 전체를 한 문맥으로 처리해서,
    의미 없는 입력 변화에도 화자를 바꿀 수 있다.
  • 기존 지표는 한 번의 실행만 보므로 이 불안정성을 놓친다 → 모든 변형에서 맞혀야 정답인 지표로 평가한다.

  • 보정 연구(DiarizationLM, AG-LSEC)는 정확도를 올리는 방법이다.
    제안 baseline도 이쪽에 가깝다.
  • 불변성 테스트(CheckList)는 NLP에 있던 원리다 → 이 원리를 통합 모델의 화자 귀속에 적용한 평가 축이 본 챌린지의 기여다.
03

과제와 평가 지표

입력과 출력

  • 입력 — 연속 회의 음성 1개, 등장 화자 2–4명의 등록 음성(각 3초 × 2개), 평가할 발화의 시작·끝 시각
  • 출력 — 각 발화의 화자 ID (등록 화자 중 하나)

변형 조건 (10가지)

통합 모델의 입력은 [등록 음성들 + 0.4초 간격] + 대화를 이어 붙인 음성 하나입니다.
대화 음성·순서·등록 내용은 그대로 두고 다음만 바꿉니다.

  • 입력 맨 앞에 무음 0, 0.5, 1.0, …, 4.0초 추가 (9가지)
  • 등록 음성 순서를 역순으로 (1가지)

발화를 잘라 따로 처리하는 임베딩 방식 모델은 이어 붙인 입력을 쓰지 않으므로 변형의 영향이 없습니다.
이 경우 10가지 조건의 예측이 같아 불변성은 자명하고,
순위는 정확도로 갈립니다.

지표

지표정의
불변 정답률 (대표)10가지 변형 모두에서 맞힌 발화의 비율.
한 번이라도 틀리면 오답
평균 / 최저 정답률변형 조건별 정답률의 평균과 가장 나쁜 조건
Flip조건에 따라 예측 화자가 바뀐 발화 수 (정답 여부와 무관한 안정성)
같은 사람 쌍질문↔답변 전환 전후, 같은 사람의 두 발화를 모두 맞힌 쌍의 수

트랙

  • Main — 길이 0.8–15초, 다른 화자와의 단어 겹침 5% 이하인 발화
  • Hard — Main에서 빠지는 어려운 발화를 4계층으로 나눔: 가벼운 겹침(5–30%), 심한 겹침(30% 초과), 짧은 발화(0.3–0.8초), 짧고 겹친 발화.
    클립 끝에서 잘린 발화는 제외
정리
  • 등록 음성이 주어진 회의에서 각 발화의 화자를 맞히는 과제를,
    내용은 그대로 둔 10가지 변형(앞 무음 9 + 등록 역순 1)으로 반복한다.
  • 대표 지표는 불변 정답률(10번 모두 맞힌 비율).
    트랙은 깨끗한 발화의 Main, 겹친·짧은 발화의 Hard.

Baseline 모델

MOSS-Transcribe-Diarize 0.9B

전사·시각·화자를 함께 출력하는 통합 모델입니다.
등록 음성을 대화 앞에 붙여 넣고,
등록 구간에 나온 익명 화자 ID로 연결합니다.

WeSpeaker ResNet34-LM

음성만 사용합니다.
발화 임베딩과 등록 음성 임베딩의 코사인 유사도로 화자를 고릅니다.
입력 변형의 영향을 받지 않습니다.

제안: 임베딩 재연결·확인

① MOSS 익명 ID를 대화 음성 임베딩으로 등록 화자에 다시 연결하고,
② 발화 임베딩이 다른 화자를 0.10 이상 더 선호할 때만 고칩니다.
전사·시각은 MOSS 그대로입니다.

모든 실행은 모델 revision, 패키지 버전, 디코딩 설정(BF16, greedy), 입력·코드 해시를 고정합니다.
기준값 0.10은 채점 전에 정했습니다.

07

주요 발견

1

통합 모델은 의미 없는 변형에 흔들립니다.

Starter에서 4인 회의 2개에서 관찰한 현상이 미관측 4인 회의 8개 중 5개에서 재현됐습니다(Main 70발화 중 23개가 조건에 따라 바뀜).
같은 입력은 항상 같은 출력을 내므로 무작위성 때문이 아닙니다.

2

무음 길이나 30초 경계와는 규칙적인 관계가 없습니다.

같은 발화가 1초에서는 맞고 0.5·1.5초에서는 틀리는 식입니다.
30초 인코더 경계에 걸리기 때문이라는 가설은 Starter 2개 대화의 대조 실험에서 지지되지 않았습니다.

3

오류는 두 유형으로 나뉩니다.

등록 음성을 화자 ID에 연결하지 못한 경우가 64%, 연결은 됐지만 대화 안에서 틀린 경우가 36%입니다(Held-out MOSS 오류 129건).

4

고정한 임베딩 재연결은 미관측 회의에서도 불변성을 회복했습니다.

Main 불변 정답률 67.1% → 98.6%, flip 23 → 0.
다만 음성 전용 WeSpeaker와 사실상 같은 수준입니다.

5

Hard 트랙은 아직 풀리지 않았습니다.

겹친 발화에서 어떤 방법도 불변 정답률 65%를 넘지 못합니다.
다음 단계의 개선 목표입니다.

한계

  • 제안 방법이 WeSpeaker보다 낫다는 근거는 아직 없습니다.
  • Held-out은 모두 4인 회의라 화자 수의 영향은 분리되지 않았습니다.
  • 질문↔답변 전환 자체가 오류를 일으킨다는 인과는 입증하지 않았습니다.
  • 겹친 발화의 정답은 해당 대화행동을 말한 사람 1명으로 정의했습니다.

평가 방법과 제출

1. 조건별 입력 만들기 (통합 모델용)

python speaker_project/make_condition_inputs.py --output condition_inputs   # 8구간 × 10조건 = 80개 WAV (약 220MB)

condition_inputs/condition_inputs.jsonl에 WAV마다 등록 음성 구간(화자 ID·초)과,
그 WAV 시간축으로 옮긴 발화 구간이 들어 있습니다.
임베딩 방식 모델은 inputs.jsonl을 바로 써도 됩니다.

2. 예측 제출 형식

조건마다 <조건>.jsonl 파일 하나,
총 10개를 한 폴더에 둡니다.
조건 이름은 pad0000ms_fwd, pad0500ms_fwd, …, pad4000ms_fwd, pad0000ms_rev입니다.

{"clip_id": "TS3010b_question_answer_reversal_01",
 "predictions": [{"segment_id": "segment_000", "speaker": "A"}, {"segment_id": "segment_001", "speaker": null}, …]}

화자는 등록 ID(A–D) 중 하나입니다.
null이나 빠진 발화는 오답으로 셉니다.
Main과 Hard 모두 채점되도록 모든 공개 발화를 예측하세요.

3. 채점

python speaker_project/evaluate_submission.py --predictions my_predictions/ --output my_score.json

Python 표준 라이브러리만 사용하며,
Main·Hard 트랙의 불변 정답률, 평균·최저 정답률, flip, 같은 사람 쌍, Hard 계층별 점수를 출력합니다.
세 baseline의 제출 파일(runs/speaker_heldout_01/submissions/)을 이 스크립트로 채점하면 위 리더보드 수치가 그대로 나옵니다.

Baseline 재현

python speaker_project/download_wespeaker.py                     # WeSpeaker ONNX 모델 (약 26.5MB, SHA256 확인)
bash speaker_project/setup_moss_reuse_torch.sh                   # MOSS 전용 환경 (기존 CUDA PyTorch 공유)
python speaker_project/run_heldout_sweep.py --shard 0/1 --output runs/heldout   # MOSS 80회 (GPU, GPU 2장이면 0/2·1/2)
python speaker_project/analyze_heldout.py --run runs/heldout     # WeSpeaker·제안 방법 계산(CPU) + 제출 파일·점수 생성
  • MOSS 실행은 runs/speaker_moss_pilot_01/run_manifest.json에 고정된 모델 revision·패키지 버전·디코딩 설정을 읽습니다.
    실제 실행: RTX A5000, PyTorch 2.4.0+cu118, Transformers 5.6.0, BF16, greedy.
    80회 추론 합계 약 26분,
    최대 GPU 메모리 약 2GB.
  • 정답 파일은 모든 예측을 만든 뒤에만 읽습니다.
    서버 원본 출력은 runs/speaker_heldout_01/results_only.zip에 있습니다.
  • 평가 데이터는 저장소에 포함되어 있습니다.
    AMI 원본 주석에서 다시 만들려면 download_ami.py → prepare_ami.py --scan-all → build_heldout.py 순서로 실행합니다(선택).
