# 2×2 실험 분석: 입력 문맥에 따른 오류와 등록 누락을 분리했다

2026-10-29. **기존 A→B 오류 2개는 동일 전체 입력에서 다시 재현됐고, 발화별 입력에서는 두 등록 순서 모두 A로 맞혔다.** 그러나 발화 분할과 등록 역순은 다른 발화에서 새 오류·누락도 만들었다. 현재 결과는 입력 구조에 따른 민감성을 보여주며, 일괄 분할이나 역순 등록을 보편적인 개선책으로 확정할 근거는 아니다.

## 검증 범위

results_only.zip은 179,860바이트, 90개 파일이며 ZIP CRC가 정상이다. ZIP 내용과 로컬에 동기화된 90개 파일이 모두 일치한다. 78개 작업의 입력 WAV·PCM 해시, 등록 구간, 평가 프레임 범위를 로컬 원본으로 재구성해 원본 실행 기록과 일치함을 확인했다. 익명 화자 매핑과 발화 투영을 78개 모두 다시 계산했고, 네 조건의 점수와 요약은 ZIP 보고서와 일치한다.

정순 전체 입력 2개는 이전 pilot과 입력 WAV, 생성 텍스트, 구간 목록이 모두 같았다. 따라서 기존 두 오류의 재현성이 이 범위에서는 확인됐다. 새로운 GPU 추론은 이 분석에서 수행하지 않았다. 청취 검토를 완료했다는 의미는 아니다.

## 네 조건의 실제 점수

모든 점수는 이번에 선정한 2개 대화의 24개 발화·3개 동일 인물 쌍에 대한 것이다. 원래 8개 대화의 70개 점수와 분모가 다르다.

| 조건 | 발화 정답 | 동일 인물 쌍 동시 정답 | 기존 두 오류 수정 | 새 오류 | 오류 구성 |
|---|---:|---:|---:|---:|---|
| 전체·정순 | 22/24 (91.7%) | 2/3 | 0 | 0 | 잘못된 등록 화자 배정 2 |
| 전체·역순 | 20/24 (83.3%) | 2/3 | 0 | 2 | 잘못된 배정 2 + 등록 ID 연결 실패 2 |
| 발화별·정순 | 21/24 (87.5%) | 3/3 | 2 | 3 | 잘못된 배정 2 + 대상 발화/시각 출력 누락 1 |
| 발화별·역순 | 23/24 (95.8%) | 3/3 | 2 | 1 | 등록 ID 연결 실패 1 |

수정·새 오류는 이번 전체·정순 재실행을 기준으로 계산했다. 같은 24개에서 기존 WeSpeaker는 24/24 정답이었다. MOSS 조건 중 최고가 23/24라는 사실을 음성 전용 방법보다 우수한 결과로 표현하지 않는다. MOSS는 전사와 시각도 생성하므로 기능·처리량은 다르다.

| 대화 | 전체·정순 | 전체·역순 | 발화별·정순 | 발화별·역순 |
|---|---:|---:|---:|---:|
| IS1009d, 원래 오류 사건 | 11/13 | 11/13 | 12/13 | 13/13 |
| IS1000d, 원래 성공 사건 | 11/11 | 9/11 | 9/11 | 10/11 |

등록 역순은 전체 입력에서 정답 2개를 줄였고, 발화별 입력에서는 정순 대비 정답 2개를 늘렸다. 등록 순서의 효과가 입력 단위에 따라 달라졌다. 두 요인의 상호작용을 시사하는 작은 표본의 관측값이지 일반적인 효과 크기 추정은 아니다.

## 1. 원래 A 오류는 전체 입력에서만 남았다

IS1009d의 동일한 두 음성 파형에 대한 결과다. 발화별 입력에서도 음량·발음·파형을 바꾸지 않았다.

| 발화 | 정답 | 전체·정순 | 전체·역순 | 발화별·정순 | 발화별·역순 |
|---|---|---|---|---|---|
| segment_001, Why … you need that up? | A | B | B | A | A |
| segment_006, I think you can make it there. | A | B | B | A | A |
| segment_019, 뒤의 Yes, I think … shape is one. | A | A | A | A | A |

기존 WeSpeaker와 MOSS의 차이에서 한 단계 나아가, **같은 MOSS에서도 입력 단위에 따라 물리적 화자 배정이 바뀜**을 확인했다. 익명 번호 S01/S04의 순열 변화는 매번 등록 시각으로 A/B/C/D에 연결했으므로 이 결과를 만들지 않는다.

전체·역순에서는 B/C 등록 병합이 사라져 네 화자가 모두 등록됐는데도 두 A→B 오류는 그대로였다. 따라서 B/C 병합만으로 두 오류를 모두 설명할 수 없다. 동일 파형을 그대로 사용한 발화별 입력에서 정답이 나오므로 음량·발화 길이 하나만으로도 충분한 설명이 되지 않는다. 이 요인들이 문맥과 상호작용할 가능성은 남는다.

분리 입력은 주변 음향·언어 문맥, 전체 길이, 음성 인코더 청크 구성과 생성·분할을 함께 바꾼다. 따라서 **의미 편향이나 질문→답변 전환의 인과 효과**가 단독으로 증명된 것은 아니다. 특히 기존 두 오류는 지정 전환 이전 발화에서 발생했다는 점이 그대로다.

추가로 확인한 구체적인 혼동 요인은 **30초 음성 인코더 경계와 발화의 시간 위치**다. 고정 모델의 로컬 preprocessor_config.json은 chunk_length=30, n_samples=480000, sampling_rate=16000을 지정하며, processing_moss_transcribe_diarize.py는 이 길이로 음성을 분할한다. 첫 오류 segment_001은 전체 입력에서 29.20–30.93초로 30초 경계에 걸치지만 발화별 입력에서는 27.20–28.93초여서 경계를 벗어난다. 같은 내용의 입력 위치·청크도 달라진 것이다.

다만 두 번째 오류 segment_006은 전체 입력의 42.87–44.01초로 30초 경계를 가로지르지 않고, 60초 경계에 걸친 다른 발화는 정답이었다. 따라서 경계 통과 여부만으로 모든 오류를 설명할 수 없다. 이 가설을 더 구분하려면 전체 대화·등록 내용은 유지하고 입력 맨 앞의 무음 길이만 바꿔 경계 위치를 이동하는 소형 검사가 가능하지만, 아직 실행하지 않았다. 시간 위치와 경계를 통제하기 전에는 순수한 대화 의미 효과로 단정하지 않는다.

## 2. 등록 순서는 병합뿐 아니라 등록 음성의 출력 누락에도 영향을 줬다

IS1000d는 정순 전체 입력에서 11/11이었다. 역순으로 등록 음성만 제시하면 C의 등록 구간이 출력되지 않아 C에 대응하는 익명 ID를 등록 시각으로 연결하지 못했다. 본 대화의 C 발화 두 개는 둘 다 S04로 출력됐지만, 등록 구간에서 S04가 한 번도 나타나지 않아 A/B/C/D 매핑에서 제외됐다.

| 조건·발화 | 실제 화자 | 원본 출력 | 채점 실패 이유 |
|---|---|---|---|
| 전체·역순, IS1000d segment_003 | C | S04, So. | S04에 연결된 등록 화자 없음 |
| 전체·역순, IS1000d segment_032 | C | S04, It is Euro frank. | S04에 연결된 등록 화자 없음 |
| 발화별·역순, IS1000d segment_032 | C | S04, It is zero frank. | S04에 연결된 등록 화자 없음 |

이는 ‘다른 등록 화자로 배정한 오류’와 분리해야 하는 **등록→익명 ID 연결 단계의 실패**다. 발화가 아예 전사되지 않은 경우와도 다르다. 전사에 생성된 화자 ID와 등록 음성 시각의 겹침만으로 연결하는 현재 어댑터의 의존성이 드러났다.

발화별·역순의 등록 미완료는 13/37회다. 사건별로 IS1009d에서 B 미연결 1/19회, IS1000d에서 C 미연결 12/18회다. 매번 누락된 사람이 대상 발화자이지는 않아 점수 대상 미예측은 1개였다. 등록 미완료 횟수와 실제 오답 수를 동일시하지 않는다. 전체·정순 1/2회와 발화별 13/37회도 호출 단위가 달라 단순 비율만으로 품질을 비교하지 않는다.

## 3. 발화 분할은 다른 발화의 유용한 정보를 잃거나 등록 경계를 만들 수 있다

발화별·정순은 원래 두 오류를 고쳤지만 세 개의 새 오류를 만들었다.

- IS1009d segment_007: D의 0.92초 Mm 'kay.를 A로 배정했다.
- IS1000d segment_005: D의 0.87초 yeah right.에 해당하는 대상 구간의 전사·시각 출력이 없었다.
- IS1000d segment_034: B의 2.42초 Uh special colour, now we leave it to the covers.를 D로 배정했다.

마지막 경우 원본 출력은 마지막 D 등록 음성과 B의 대상 발화를 **하나의 S04 구간으로 이어 전사**했다. D 등록은 약 20.40–26.80초이고, 대상 B는 27.20초부터인데, 모델 출력은 20.36–29.62초의 한 S04 발화로 합쳤다. 등록 접두부와 평가 발화를 연결한 인공 경계의 영향도 점검해야 한다. 이 단일 사례로 모든 오류를 마지막 등록 화자에 대한 편향으로 일반화하지 않는다.

역순 발화별 조건에서는 위 세 오류가 없어졌지만 C의 등록 연결 실패가 새로 생겼다. 따라서 ‘역순이 항상 좋다’, ‘분할하면 항상 좋아진다’는 규칙으로 정리하기 어렵다.

## 4. 쌍 점수 3/3이 모든 전환 뒤 발화의 성공을 뜻하지 않는다

IS1000d의 segment_034는 실제 전환 뒤 답변이다. 그런데 같은 B의 앞선 질문은 0.44초로, 0.8초 기준을 만족하지 않아 B의 질문→답변 쌍 전체가 점수에서 빠졌다. 따라서 발화별·정순은 이 후반 답변을 틀렸는데도 쌍 점수는 3/3이다.

| 추가 진단 | 전체·정순 | 전체·역순 | 발화별·정순 | 발화별·역순 |
|---|---:|---:|---:|---:|
| 지정 후반 답변 정답 | 2/2 | 2/2 | 1/2 | 2/2 |

동일 인물 쌍 동시 정답률은 계속 사용할 수 있지만, 전체 발화 정답률·후반 답변 단독 점수·누락률을 함께 제시해야 한다. 이번 결과로 쌍 기준을 몰래 바꾸거나 짧은 발화를 뒤늦게 점수에 포함시키지는 않았다. 다음 데이터 구성에서 매우 짧은 질문을 어떻게 취급할지 미리 정할 필요가 있다.

## 실행 비용

78개 추론 합계는 약 385.37초, 약 6분 25초다. 모델 로딩·입력 구성·파일 쓰기 등의 총벽시계 시간과는 다르다. 최대 PyTorch 할당 VRAM은 약 1.90GiB였다. 환경은 A5000, PyTorch2.4/cu118, Transformers5.6, BF16로 유지됐다.

## 주제와 개선 방향에 대한 판단

주제의 실험 근거는 전보다 강해졌다. 동일한 자연 대화 음성·동일 모델에서도 입력 문맥과 등록 제시 방식에 따라 실제 발화 귀속이 달라지는 사례를 확보했다. 등록 오류·실제 화자 오배정·전사/시각 누락이 섞인 총점만으로 설명하면 이 차이를 놓친다.

현재 description에 쓸 수 있는 구체적인 범위는 **‘자연 대화의 화자 귀속 안정성을 평가하고, 대화 문맥·등록 제시 순서·등록 연결 실패를 분리 진단한다’**다. ‘질문/답변 전환 때문에 오류가 난다’, ‘의미 편향을 증명했다’, ‘분할·역순이 새로운 우수한 방법이다’는 주장은 아직 지지하지 않는다. 기존 연구와의 차이를 검증하기 전에는 세계 최초라고 표현하지 않는다.

다음 작업의 우선순위는 다음과 같다.

1. 해당 발화와 등록 음성을 청취 검토하고 AMI 라벨·경계를 확인한다.
2. 등록 ID 연결을 전사 출력에만 의존하는 부분을 보완한다. 미등록 익명 ID를 음성 임베딩으로 검증하는 것은 후보지만, 단순히 남은 ID를 강제 배정하면 모델의 화자 분열·새 ID 생성에서 잘못 연결할 수 있다. 기존 결과와 별도 방법으로 검증해야 한다.
3. 오류를 확인하지 않은 별도 회의에서 원래 방법과 후보 개선을 비교한다. 지금 두 대화의 최고 조합을 골라 최종 성능으로 제시하지 않는다.
4. 리더보드에는 전체·쌍 점수와 함께 등록 성공률, 등록 ID 미연결, 대상 출력 누락, 신규 오답을 구분한다. 음성 전용 WeSpeaker 기준도 유지한다.

지금 단계에서 같은 두 대화의 조합을 더 많이 탐색하는 것보다, 실패 단계를 분리한 개선 한 개와 새 대화 검증에 집중하는 편이 다음 판단에 도움이 된다.
