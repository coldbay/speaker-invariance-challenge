# 경계 대조 8회 분석: 30초 경계 가설은 기각, 등록 ID 연결이 가장 큰 불안정 요인

2026-10-29. **IS1009d의 기존 A→B 오류 2개는 30초 경계를 피한 2초·32초 조건에서도 그대로 남았다.** 경계 정렬이 원래와 같은 30초 조건에서만 두 오류가 사라졌다. 따라서 이 표본에서는 "30초 경계를 가로질러서 틀렸다"는 설명이 성립하지 않는다. 가장 큰 점수 변화(pad_32의 IS1000d 7개 새 오류)는 대화 쪽 화자 구분이 아니라 **등록 음성의 익명 ID 연결 실패 1건**에서 나왔다. 두 합의 보정은 점수를 바꾸지 못했고, 단순 합의는 채점 대상이 아닌 발화 하나를 새로 틀렸다.

## 1. 30초 경계 가설: 이 표본에서는 지지되지 않음

| IS1009d 발화 (정답 A) | 0초 | 2초 | 30초 | 32초 |
|---|---|---|---|---|
| segment_001 "Why … you need that up?" | B (경계 걸침) | B (경계 1.2초 밖) | **A** (경계 걸침) | B (경계 1.2초 밖) |
| segment_006 "I think you can make it there." | B | B | **A** | B |
| segment_019 "Yes, I think uh shape is one." | A | A | 누락(S04 미연결) | A |

- 설계 문서의 판정 기준("0/30에서 반복, 2/32에서 해소면 경계 민감성")과 정반대 패턴이다. 경계를 피한 2·32초에서 오류가 남고, 경계에 걸친 30초에서 고쳐졌다.
- segment_006은 네 조건 모두 경계에서 12초 이상 떨어져 있었는데 똑같이 바뀌었다. 두 오류가 항상 함께 움직이므로 원인은 발화 위치가 아니라 **A 화자 클러스터 전체의 ID 배정**으로 보인다. pad_30에서는 A의 앞 두 발화가 S01(A 등록)로 가는 대신 뒤의 segment_019가 새 ID S04로 갈라졌다. 즉 A 목소리가 둘로 나뉘는 위치만 바뀌었다.
- 30초 조건은 앞에 빈 인코더 청크 하나가 추가되고 전체 길이도 달라진다. 이 경우만 다른 결과가 나왔으므로 정렬보다 **절대 위치·길이·빈 청크에 대한 비체계적 민감성**으로 해석하는 것이 맞다. 4개 조건 1회씩이라 어느 요인인지 분리하지 못한다.

## 2. 가장 큰 변화는 등록 ID 연결 실패

| 대화 | 0초 | 2초 | 30초 | 32초 |
|---|---|---|---|---|
| IS1009d | B·C 등록이 S02로 병합 (3/4) | 4/4 | B·C 병합 (3/4) | 4/4 |
| IS1000d | 4/4 | 4/4 | 4/4 | **B·D 등록이 S02로 병합 (3/4)** |

- **IS1000d pad_32의 7개 새 오류는 한 건의 연결 실패에서 나왔다.** 대화 부분 자체는 정상적으로 구분됐다(B 발화는 S02, D 발화는 S04로 다른 조건과 같음). 그러나 D 등록 음성 52.37–58.77초가 S02로 출력되어 S02의 등록 근거가 B 3.25초 / D 5.97초가 되었고, 최대 근거 규칙으로 S02→D가 됐다. 그 결과 B 발화 5개가 D로, D 발화 2개(S04)가 미연결 누락이 됐다.
- B 등록의 출력 근거는 모든 IS1000d 조건에서 3.25–3.30초로 짧다("Um", "and um well"). 근거가 약한 등록이 다른 화자의 등록과 합쳐지면 한 대화 전체가 무너지는 구조다.
- IS1009d의 B/C 병합은 0·30초(같은 정렬)에서 함께 나타나고 2·32초에서 함께 사라졌다. 정렬과 일치한 유일한 패턴이지만, IS1009d의 채점 대상에는 B/C 발화가 거의 없어 점수에는 영향이 없다.
- 이전 2×2 진단의 full_reverse 신규 2개 오류(IS1000d C 등록 출력 누락)도 같은 유형이다. 지금까지 관측된 새 오류의 대부분이 "등록 구간의 전사 출력으로 ID를 잇는 단계"에서 생겼다.

## 3. 합의 보정은 효과가 없고, 단순 합의는 숨은 오류를 만든다

- 기존 A 오류는 네 조건 중 3개가 같은 B로 틀렸다. 단순 합의(75%)는 오답 B를 그대로 확정했다. 보수적 보정은 만장일치가 아니어서(B,B,A,B) 원래 예측을 유지했다. "네 조건 모두 같은 화자로 틀리면 보정하지 못한다"는 설계상 한계가 3/4에서도 사실상 적용된다.
- pad_32의 B→D 7개는 다른 세 조건이 B로 맞혔으므로 두 방법 모두 B를 유지했다. 합의가 한 조건의 붕괴를 막는 역할은 했지만 pad_00 대비 개선은 아니다.
- **단순 합의는 IS1000d segment_022(정답 B, 채점 제외 짧은 발화 "but, actually bu")를 B→A로 바꿨다.** 2·30·32초 투표는 대상 구간의 41–48%만 덮는 약한 근거였다. 채점 지표에는 보이지 않는 새 오류다. 대상 구간 50% 규칙을 둔 boundary_guard는 이를 막았다.

## 결론과 다음 단계

1. 30초 청크 길이 변경이나 경계 회피 입력은 현재 오류의 해결책으로 근거가 없다. 경계 가설은 이 2개 대화에서 기각하고, 이후 보고서에서 의미 편향·경계 효과 모두로 단정하지 않는다.
2. 우선 개선 대상은 등록 ID 연결이다. BOUNDARY_IMPROVEMENT.md 3단계(고정 등록 프로토타입과 음성 임베딩으로 익명 ID를 등록 화자에 연결)가 pad_32·full_reverse 유형의 붕괴를 직접 겨냥한다. 단, IS1009d A→B 오류는 대화 쪽 클러스터 자체가 B와 합쳐진 경우라서 ID 단위 연결만으로는 고쳐지지 않고, 발화(또는 익명 구간) 단위 임베딩 재확인이 필요하다.
3. 이 2개 대화는 이미 여러 번 분석해 설정 선택에 사용했으므로, 어떤 보정을 고르든 새 회의에서 검증해야 한다.
4. 각 조건이 1회씩이라 변동 폭(분산)은 추정하지 못했다. 결정적 디코딩이므로 반복은 같은 결과를 낸다. 대신 무음 길이를 더 촘촘히(예: 0–4초 0.5초 간격) 바꾸는 것이 민감도 추정에 더 유용하다.
